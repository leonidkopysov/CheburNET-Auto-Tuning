# ЧебурNET Auto Tuning 1.0.1

Обновление по результатам технического аудита.

- Проверка ошибок записи конфигов и блокировка параллельных запусков.
- ZRAM: без сброса устройств неизвестного назначения; обновление собственного
  helper при активном swap; корректный пропуск большого пакета по выбору.
- APT: видимый прогресс, предупреждение о длительности, прекращение дальнейших
  установок после таймаута/прерывания.
- UFW: проверка чтения портов, сохранение пропущенного порта панели, снимки и
  попытка отката при ошибке; общий lock операций firewall с Certbot helper.
- RPS: проверка реальных масок, исправление global-only проверки и миграция helper.
- NOFILE: независимая проверка soft/hard. Compose: явное согласие на recreate,
  фиксированный project, приватный снимок конфигурации и попытка отката.
- SSH: проверка эффективных значений; сохранение более строгого root policy;
  автоматические изменения запрещены без подтверждённого входа по ключу или
  при обнаружении Match-блоков в стандартных конфигурационных файлах.
- Уточнены проверки APT, Certbot, прав и публичных портов; обработка EOF,
  десятичных портов с ведущими нулями и длинных числовых значений.
- Перенос длинных стандартных сообщений с учётом кириллицы; обозначены значения
  Enter; унифицированы значки post-reboot отчёта.
- Traffic-Control и TrafficGuard не включены.

## Новые подтверждения

`CHEBURNET_ALLOW_NODE_RECREATE=1` — разрешить пересоздание ноды без вопроса.
Без переменной скрипт спрашивает; неинтерактивно пересоздание пропускается.

`CHEBURNET_SSH_KEY_LOGIN_CONFIRMED=1` вместе с `CHEBURNET_HARDEN_SSH=1` —
подтверждение, что администратор уже проверил отдельный вход root по ключу
и имеет аварийную консоль. Скрипт сам SSH-ключи не создаёт.

## Проверки и ограничения

Bash, ShellCheck и изолированные регрессионные тесты. Сценарии не выполняют
установку пакетов, создание swap или смену firewall на проверяющей машине.

Релиз не является подтверждением полной production-приёмки на всех сочетаниях
Ubuntu 22.04/24.04, Debian 12 и amd64/arm64. Фактический доступ через firewall,
SSH Match/Include нестандартных путей и полное восстановление Docker требуют
проверки на конкретном сервере. Автооткат — попытка, не гарантия сохранения связи.
Перед первым запуском нужен снимок VPS и доступ к консоли провайдера.
